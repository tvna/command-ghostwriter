# テンプレートライブラリ左レールの再編: 4ラベルを50件未満に分割

Refs #631, #501

## 1. 目的

テンプレートライブラリ左サイドバーの「カテゴリレール」22項目のうち、4項目が50件以上に肥大化し、可視性(一覧性)を損なっている。該当4項目を、既存の `subCategory` 値をグルーピングする形で50件未満の複数ラベルに分割する。

## 2. 背景

- 2026-08-01時点(PR #628マージ後)のレール件数: サーバ(共通)216・ネットワーク機器(共通)123・AIインフラ114・ミドルウェア88 がいずれも50件以上。他18項目(ops/facility含む)と、内部の `subCategory` グリッド見出し(94種、最大29件)はすでに全て50件未満。
- 直近でIssue #625 / PR #628(コンテナ統合)がサーバ共通・AIインフラを部分的に圧縮済み(227→216、117→114)。本設計はその続きとして残る4項目を扱う。
- Issue #619(NGFW系ベンダーテンプレート追加、未実装)はFortinet(29)・Palo Alto Networks(26)・SonicWall(26)をさらに増やす見込みだが、個別ベンダーレールは現時点で50件未満であり本設計のスコープ外。
- オーナー決定(ブレインストーミング対話にて確認済み):
  - 「ラベル」は左レールの表示単位を指す(トップレベル `category` ではない)。
  - 継続的な50件制約を強制するCIドリフトゲートは今回は追加しない(手動監視を許容)。
  - 新設ラベル名は10文字以内とする。

## 3. 決定事項

### 3.1 実現方式: `Library.tsx` のみの変更

新しいレール区分けは、既存の `subCategory` 文字列の集合(Set)メンバーシップとして表現する。既存の `NETWORK_VENDORS` 配列・`SERVER_SPLIT_LABELS` と同じ「フィルタ述語 + グルーピング見出し」の仕組み(`RailEntry.filter`)を拡張するのみで、`templates.ts` のテンプレートレコード・`types.ts` の型・`test_template_taxonomy.py` の許可リストへの変更は一切不要。`groupBySubCategory` は `(category, subCategory)` で汎用的にグルーピングする既存実装のままで、複数 `subCategory` にまたがるレール選択でも正しく複数セクション見出しを表示する。

下表の「内訳」列はいずれも同一 `category` 内の `subCategory` のみを列挙している(例: サーバ側の「監視」はnetwork/middlewareの同名 `subCategory` と別物)。フィルタ述語は既存パターンと同様に `category` の等価判定と `subCategory` のSetメンバーシップ判定を常にAND条件で組み合わせ、バケットをまたいだ意図しない包含が起きないようにする。

検討した代替案:

- **`subCategory` 自体を統合・改名する案**(過去のmiddleware統合と同様の手法): グリッド見出しも同時に整理できる利点はあるが、200件超のレコードを書き換える大きな差分になり、`templates.ts` のリスクを増やすため不採用。「テンプレート帰属を50件未満に」という要望に対しては過剰な変更。
- **6ドメイン(`category`)自体の再定義**: #570/#571/#615で確立した安定構造であり、今回のスコープ外。壊す理由がない。

### 3.3 グループ見出し

左レールの `group` 見出しは既存の「ネットワーク機器」「サーバ」を維持し、新たに「AIインフラ」「ミドルウェア」をグループ見出しとして追加する(各3エントリを束ねる)。`ops`(43件)・`facility`(20件)は現状の単独レールのまま「その他」グループに残す(いずれも50件未満のため対象外)。

### 3.4 ラベル文字数

全13新規ラベルの括弧内テキストは10文字以内(オーナー制約)。最長は「VPN・オーバーレイ」「ネットワークサービス」の各10文字(いずれも制約ちょうど)。

## 5. 検証

- `cd web && bunx tsc -b` — 型エラーなし。
- `cd web && bun run test` — 更新後の `Library.test.tsx` を含め全件green。
- `uv run pytest -k 'not e2e'` — 無変更のはずだが回帰確認として実行。
- 手動スモーク: Library UIを開き、新設13ラベルすべてをクリックして件数がこの設計書の表と一致すること、空セクション・重複セクション見出しがないことを確認。

## 6. リスク

- **クラスタ分類は `subCategory` 名からの分類であり、実テンプレート内容(`.j2` 本体)の個別監査は未実施。** 過去の類似設計(#501, #625等)は必ず内容監査を行っていたが、本変更は表示グルーピングのみで `templates.ts` のデータは変更しないため、誤分類があってもテンプレートの機能・IDには影響しない(低リスク)。実装時に軽く目視確認することが望ましい。
- **上限に近いラベルが2件**: 「サーバ (監査・資産)」49件、「AIインフラ (モデル・推論)」48件。ドリフトゲート未導入のため、将来のテンプレート追加で再び50件を超える可能性がある。オーナー決定により今回は許容し、手動監視に委ねる。
- Issue #619(NGFW系テンプレート追加)が実装されると個別ベンダーレール(Fortinet等)が50件に近づく可能性があるが、本設計のスコープ外。
