# 設計: AIインフラテンプレート100本の追加

- Issue: #576
- ブランチ: claude/ai-infra-templates-100-cr1919
- 日付: 2026-07-17

## 背景と目的

テンプレートライブラリの `ai` カテゴリは現在17件（NVIDIA DGX, GPU基盤, GPU監視,
GPUコンテナ, モデル管理, 推論サーバ, APIゲートウェイ, step-ca / Caddy）で、オン
プレGPUサーバの初期構築・監視・モデル運用が中心である。オーナーの依頼により、
この系列に新規100件を追加する。オーナーは範囲確認の質問に対し「オンプレミス以
外も全て承認」と回答しており、クラウドAIサービス・エージェント/RAG応用基盤ま
で含めた全方位カバレッジとする。

実行体制はオーナー指定のとおり: `fable` サブエージェントが各クラスタの具体的な
100件仕様を計画し、`sonnet` によるダイナミックワークフロー（Workflowツール）で
並行実装する。直近の類似実績（#567/#568「200テンプレート追加」、進行中の#574
「315テンプレート追加」）が同じ体制・単一PR配信のパターンを既に確立しており、
本設計もそれに倣う。

## 変更内容

### 1. テンプレート実体（`assets/examples/`）

既存の慣例（`<id>.<format>` + `<id>.j2` のペア、kebab-case id）に従い、100組
（200ファイル）を追加する。各 `.j2` は以下の6セクション構成で書く:

1. タイトル + 1〜2文の導入
2. `## 目的` — このテンプレートで何ができるようになるか
3. `## 用語解説` — 専門用語の解説（テンプレート本文に直接記述、データ変数化不要）
4. `## シナリオ設定` または `## 背景` — 前提となる構成・状況
5. `## 手順` — `###` 番号見出し + bashコードブロックによる具体的なCLI操作
6. `## 動作確認` — 手順完了を確認するチェック項目
7. `## 注意事項` — 安全警告・前提条件・破壊的操作の影響範囲・ロールバック手段

### 2. Web UI登録

- `web/src/lib/types.ts`: 変更なし（`TemplateCategory`/`TemplateActivity` は
  #570の是正で既に確定済みの型を使う）
- `web/src/lib/templates.ts`: `META` 配列に100エントリを追加
  （`category: "ai"`, `output: "markdown"`, `live: true`,
  `updated: "<実装日>"`）。並行実装される100件は個別agentがテンプレート実体を
  作成し、`META` エントリの本追記は競合を避けるため最後に単一の編集でまとめて
  行う（#567の手法を踏襲）
- `tests/unit/test_template_taxonomy.py`: `ALLOWED_SUBCATEGORIES["ai"]` に
  新規7サブカテゴリ（`GPUクラスタ`, `ベクトルDB`, `MLOps`, `監視・可観測性`,
  `セキュリティ・ガバナンス`, `エージェント基盤`, `クラウドAI`, `データ基盤`）
  を追加する

### 3. 変更しないもの

- Pythonコア（`features/`）・レンダリングエンジン: 変更不要
- `web/src/components/Library.tsx` の `CATS`: `ai` カテゴリは既存のため変更不要
- README のユースケース例: テンプレートはライブラリUIから発見可能なため追記しない

## 既知の落とし穴（実装エージェントへの申し送り事項）

直近のレトロスペクティブ（#569, #571）で判明した、レンダー成功だけでは検出でき
ない失敗クラスを踏襲する。各テンプレートは以下を満たすこと:

1. **strict-undefined レンダー成功**: テンプレートで参照する全変数がデータファ
   イルに存在すること
2. **HTMLエンティティ非混入**: autoescapeにより `&&` `<` `>` `"` 等がHTMLエン
   ティティ化されないこと。シェルのメタ文字はデータ変数経由ではなくテンプレー
   ト本文のリテラルとして書く
3. **fill不変性**: CSVデータを使う場合、空セルの有無で出力が変わらないこと。
   `{% if r["x"] %}` のような空セルの truthy 判定は禁止し、`"-"` 等の明示的な
   センチネル値で `{% if r["x"] != "-" %}` のように比較する
4. **runtime-security**: CSV行の添字に対して直接メソッド呼び出しをしない
   （例: `r["x"].split(",")` は禁止）。値はCSV列として事前計算するか、シェル
   側（`tr`/`cut`等）で分割する

## 実行体制

1. **Issue起票**: CLAUDE.md 3節に従い、本ドキュメント確定前にGitHub issue #576
   を起票済み。以降の全コミットで参照する
2. **計画フェーズ（fable）**: クラスタごとに `Agent`（`model: "fable"`）を呼び、
   12件程度の候補ブレインストーミング→上位10件選定を依頼する。既存246件+選定
   済み他クラスタのidリストを渡し重複を避ける。出力は id/name/desc/subCategory
   /format/activity の構造化スペック
3. **実装フェーズ（sonnet, ダイナミックワークフロー）**: `Workflow` ツールで
   100件を `pipeline()` により並行処理する。各件のステージは
   (a) テンプレート実体（`.j2`+データファイル）の作成、
   (b) `scripts/local_render_check.py <id>` によるレンダー検証、
   (c) 検証失敗時の修復（最大数回のループ）
4. **統合フェーズ**: 全件のステージ完了後、`templates.ts` の `META` 配列と
   `test_template_taxonomy.py` の `ALLOWED_SUBCATEGORIES` を単一の編集でまとめ
   て更新する
5. **検証**: `uv run pytest tests/unit/test_example_templates_render.py
   tests/unit/test_template_taxonomy.py -k 'not e2e'`、
   `python3 scripts/local_render_check.py` の全件実行、可能であれば
   `web` の `tsc --noEmit` / lint / gitleaks / typos
6. **コミット/push**: クラスタ単位など変更サーフェスが把握しやすい粒度で分割コ
   ミットし、各コミットでissue番号を参照する。designated branchへpushする。
   PRはオーナーからの明示的な依頼があるまで作成しない

## エラーハンドリング

`templates.ts` の `file()` はアセット欠落時に throw する既存ガードがあり、ペア
漏れはビルド/テストで即検出される。`test_template_taxonomy.py` の
`ALLOWED_SUBCATEGORIES` チェックは未申告のサブカテゴリを即座に検出する。追加の
チェックは設けない。

## 検証（この環境で実行可能なものすべて）

1. **本物のレンダリングエンジンでの描画確認**: `scripts/local_render_check.py`
   （strict-undefined + HTMLエンティティ + fill不変性 + runtime-security の
   4invariant）を全新規100件に対して実行
2. **型・単体テスト**: `uv run pytest tests/unit/test_example_templates_render.py
   tests/unit/test_template_taxonomy.py`
3. **web側**: `cd web && npx tsc --noEmit`（環境のネットワーク可否に応じて
   `bun install` 実行可否を確認したうえで実施。実行不能な場合はその旨を明記
   し、代替として `templates.ts` の構文（TypeScriptオブジェクトリテラルとして
   の妥当性）を目視確認する）
4. **lint**: 利用可能な範囲で ruff/gitleaks/typos/yamllint を実行

E2E（render-parity）はテンプレート内容に依存しないため対象外。
